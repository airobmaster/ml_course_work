All classification models will be evaluated on exactly the same validation set.

- Accuracy
- Macro-F1 — useful for understanding performance across classes
- Weighted-F1 — accounts for class frequency

CELL 88 code
from sklearn.metrics import (
    accuracy_score,
    classification_report,
    confusion_matrix,
    f1_score,
)


validation_results = []


def evaluate_model(model_name, y_true, y_pred):
    """Evaluate a multiclass classifier and store validation metrics."""

    metrics = {
        "Model": model_name,
        "Micro-F1": f1_score(y_true, y_pred, average="micro"),
        "Accuracy": accuracy_score(y_true, y_pred),
        "Macro-F1": f1_score(y_true, y_pred, average="macro"),
        "Weighted-F1": f1_score(y_true, y_pred, average="weighted"),
    }

    validation_results.append(metrics)

    print(f"\n{model_name}")
    print("-" * len(model_name))
    print(f"Micro-F1    : {metrics['Micro-F1']:.4f}")
    print(f"Accuracy    : {metrics['Accuracy']:.4f}")
    print(f"Macro-F1    : {metrics['Macro-F1']:.4f}")
    print(f"Weighted-F1 : {metrics['Weighted-F1']:.4f}")

    print("\nClassification report:")
    print(
        classification_report(
            y_true,
            y_pred,
            digits=4
        )
    )

    return metrics

CELL 97 code
import lightgbm as lgb


LGB_CATEGORICAL_COLS = [
    *GEO_COLS,
    *CATEGORICAL_COLS,
]


def prepare_lgb_data(train_df, valid_df=None, categorical_cols=None):
    """Convert categorical columns to aligned pandas categorical dtype."""

    categorical_cols = categorical_cols or []

    train_out = train_df.copy()
    valid_out = None if valid_df is None else valid_df.copy()

    for col in categorical_cols:
        train_out[col] = train_out[col].astype("category")

        if valid_out is not None:
            valid_out[col] = valid_out[col].astype("category")
            valid_out[col] = valid_out[col].cat.set_categories(
                train_out[col].cat.categories
            )

    return train_out, valid_out

### 4.7 LightGBM Hyperparameter Tuning

Rather than performing a very large hyperparameter search, this uses `RandomizedSearchCV` over a deliberately narrow range based on the behaviour observed during model development.

The search focuses on:

- `num_leaves`
- `min_child_samples`
- `colsample_bytree`

The learning rate and number of estimators are kept fixed to control the search space.

The search itself uses stratified 3-fold cross-validation and Micro-F1 as the optimization metric.

### Model Results Summary

All models below were scored on the **same held-out validation set** (52,121 buildings; classes 1/2/3 with support 5,025 / 29,652 / 17,444).

|---|---|---|---|
| Logistic Regression (baseline) | 0.6966 | 0.6713 | 0.7025 |
| Random Forest (baseline) | 0.6996 | 0.6676 | 0.7015 |
| XGBoost (baseline) | 0.7267 | 0.6626 | 0.7182 |
| LightGBM (baseline) | 0.7527 | 0.7074 | 0.7492 |
| **LightGBM (RandomizedSearchCV tuned)** | **0.7532** | **0.7078** | **0.7497** |

**Hyperparameter search (`RandomizedSearchCV`, 3-fold stratified CV):** best CV Micro-F1 = 0.7452, with `num_leaves=25`, `min_child_samples=150`, `colsample_bytree=0.7`, `subsample=0.8`.

**5-fold stratified CV of the tuned LightGBM:** Mean Micro-F1 = 0.7499, Std = 0.0017, Min = 0.7480, Max = 0.7515.

**Inference**

- **LightGBM is the clear and final choice.** It leads on every aggregate metric among the baselines, and its native handling of the high-cardinality `geo_level_3_id` (and other categoricals) as categories — rather than one-hot expansion — is a practical advantage the other models don't share.
- **Tuning added very little (+0.05 pp Micro-F1 over the untuned baseline: 0.7527 → 0.7532).** The narrow, experience-guided search range was already close to optimal, so most of LightGBM's advantage comes from the algorithm/feature-handling choice, not hyperparameter search.
- **The 5-fold CV (mean 0.7499, std 0.0017) confirms the ~0.75 Micro-F1 is stable, not a lucky split** — the tight spread (0.7480–0.7515) shows the model generalizes consistently across resamples of the data.
- **Tree-based models beat the linear baseline on accuracy, but not uniformly on Macro-F1.** Logistic Regression's `class_weight="balanced"` trades precision for recall on the minority class (Grade 1: recall 0.85 vs. precision 0.44), which keeps its Macro-F1 (0.6713) competitive despite much lower overall accuracy — while XGBoost's higher accuracy (0.7267) comes with a lower Macro-F1 (0.6626) because it favors the majority classes and under-recalls Grade 1 (recall 0.45).
- **Grade 2 (the majority class) is predicted reliably by every model** (LightGBM F1 = 0.797), while **Grade 1 (the minority class) remains the hardest to separate** across all models — the main lever for further improvement is feature engineering (e.g., geographic aggregates, structural interactions) rather than additional hyperparameter tuning.
